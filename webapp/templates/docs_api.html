API & webhook docs

Everything here works today, against your real account - there's no separate sandbox. Generate a key and set a webhook from Settings first, then come back here.

Authentication

Every request needs your API key as a Bearer token. Keys are account-wide (same scope as your team), and there's only ever one live key - generating a new one retires the old.

Authorization: Bearer kauli_live_…

A missing or invalid key returns 401. Requests are rate-limited (120/minute per IP) - a burst over that returns 429 with a retry_after-style message.

Check an order's status

Returns the order's real status plus a deliverables object - only the files that order actually paid for, each a signed URL valid for 7 days that needs no login to use.

GET /api/v1/orders/{order_id}
Authorization: Bearer kauli_live_…

Example response - a translate-only order, ready, so it has srt/vtt but no audio (that order never bought dubbing):

{
  "id": "36155eb8be",
  "status": "ready_for_delivery",
  "ready": true,
  "original_filename": "interview.mp3",
  "service_level": "translate",
  "source_lang": "sw",
  "target_lang": "en",
  "created_at": 1787759945.24,
  "deliverables": {
    "transcript": "https://kauli-forgemedia.com/api/v1/deliverables/36155eb8be/transcript?expires=...&sig=...",
    "srt": "https://kauli-forgemedia.com/api/v1/deliverables/36155eb8be/srt?expires=...&sig=...",
    "vtt": "https://kauli-forgemedia.com/api/v1/deliverables/36155eb8be/vtt?expires=...&sig=..."
  }
}

GET /api/v1/orders?limit=25 (max 100) lists your most recent orders in the same shape, newest first.

Webhook

Set a URL in Settings and we'll POST to it the moment an order reaches "ready for delivery" - no polling needed. Must be a real, public https:// address; anything resolving to a private/internal network is rejected.

POST <your URL>
Content-Type: application/json
X-Kauli-Timestamp: 1787760000
X-Kauli-Signature: sha256=<hex digest>

{"event": "order.ready", "order": { …same shape as GET /api/v1/orders/{id} above… }}

Verify it really came from Kauli by recomputing the signature yourself and comparing (never with == - use a constant-time compare):

import hmac, hashlib

expected = hmac.new(
    your_webhook_secret.encode(),
    (timestamp + ".").encode() + request_body_bytes,
    hashlib.sha256,
).hexdigest()

if not hmac.compare_digest(expected, signature_header.removeprefix("sha256=")):
    reject()  # not really from Kauli

One attempt per event, no automatic retry yet - if your endpoint is down when it fires, the delivery just gets logged as failed (see the table on Settings). The same information is always available on demand via GET /api/v1/orders/{id}, so nothing is lost, just not pushed.

Common errors

StatusMeaning
401Missing/invalid/revoked API key.
404Order doesn't exist, isn't yours, or that deliverable isn't part of what this order bought.
403A deliverable link expired (7 days) or its signature doesn't match - call the order endpoint again for a fresh one.
429Too many requests - back off and retry after the interval given.
