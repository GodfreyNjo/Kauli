Forge Media Services / Kauli

Technical overview

How Kauli actually works, end to end — the pipeline, the data model, the infrastructure it runs on, and the real engineering decisions behind each, not a generic architecture template.

System at a glance

One request's real path through the system, and the one path that runs independently of it every night.

Deliberately one VM, one Docker container, one SQLite file. webapp/worker.py processes one background job at a time by design — there's no task queue yet, so a second app instance would let two jobs race each other writing to the same order. Scaling to more instances is a real, known future step (a real queue first), not an oversight.

The pipeline

Every order moves through the same three stages, each behind a provider interface so a "free" and a "paid" implementation are interchangeable at runtime, per order.

  • 01 · ASRSpeech → text. faster-whisper (free, local, CPU) is the default; Transkriptor (paid, real API) is the primary path for orders that request it, with automatic fallback to faster-whisper on any failure. Kikuyu has no viable ASR model at all yet — those orders route to a human transcriber from the start, not a bad transcript to correct.
  • 02 · MTText → translated text, 4 candidates per segment (literal / spoken / shorter / longer) picked to fit the dubbed slot's real timing budget. local (MarianMT, free, weak — an explicit placeholder) / Claude / Lara (real adaptive NMT, small free tier). Speaker tags, bracket sound-cues ([Applause]) and paragraph breaks are swapped for placeholder tokens before the text ever reaches an MT provider, and restored after — never sent for "translation" in the first place.
  • 03 · TTSTranslated text → dubbed audio, fitted to the segment's real time slot via a pitch-preserving ffmpeg stretch (never a pitch-shifting resample). Piper (free, local, five real voice presets) or XTTS (real voice cloning of the source speaker — gated server-side on the client's explicit consent, not just a UI checkbox). A non-speech gap (music, applause, laughter) is never synthesized — the real source audio for that exact window is carried straight through instead.
The one rule everything else defers to

A human edit always wins, at every layer — a hand-corrected transcript, a hand-edited translation, a manually chosen voice. Nothing a later automated pass produces silently overwrites what a person already fixed. Every order also requires 100% of its segments reviewed before it can ship — flagged or not.

Data model

Two real dataclasses carry a job from upload to delivery; everything else (orders, users, billing, messages) lives in SQLite.

Job

One real media file. Holds segments (below), the provider names actually used (not just requested — a real ASR fallback shows up here), speaker_voices (a speaker id → a consistent TTS voice, so the same character keeps the same voice across the whole file), and real cost tracking.

Segment

One real stretch of audio — either speech (source/target text, per-word timing, a chosen candidate, review flags) or gap (non-speech; carries the real source audio bed, never synthesized text). final_text always resolves a human edit over the AI draft.

The web layer

FastAPI + server-rendered Jinja2 — no separate frontend build, no API/SPA split.

RoleWhat it can reach
ClientPlaces orders, pays, downloads deliverables, messages staff on an order thread. Never sees staff tooling.
StaffThe Ereri editor, CRM, billing, exceptions queue. Admin staff additionally manage the voice-actor roster and the admin panel.
Voice actorA real third role on the same Supabase-backed auth system — self-service login, sees only their own assigned orders, uploads a finished recording that becomes the delivered file directly.

Infrastructure & ops

  • ComputeHetzner Cloud, cx23 (2 vCPU / 4GB), Falkenstein, Germany.
  • IngressNamed Cloudflare Tunnel — zero inbound ports open on the VM's firewall at all; the app never has a public IP to attack.
  • ContainerOne Docker image, CPU-only torch pinned explicitly (a plain install pulls multi-GB CUDA libraries no GPU-less VM will ever use).
  • BackupsNightly, to Cloudflare R2 — a consistent SQLite snapshot via the database's own online-backup API (safe against a live, WAL-mode file), plus an incremental sync of every real client upload and delivered output.
  • SecuritySSH key-only (no password auth), automatic OS security updates, secrets in a root-only .env file, never baked into the image.

Testing

Real pipeline tests, not mocked-everything — including a stub-everything speed path (StubMT's literal echo-back behavior is itself used as a real correctness harness: any leaked placeholder token proves the protect/restore mechanism broke) and tests that build real audio waveforms in numpy to prove the mixer never sums two overlapping segments into one clipped, distorted track. 24 tests, run before and after every deploy.
